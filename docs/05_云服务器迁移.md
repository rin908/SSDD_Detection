# 05 云服务器迁移

Linux 使用同一源码、配置和数据协议，不改路径常量。平台变化只需要安装相同版本的 manylinux wheel；数据位置变化只设置数据根。

## 1. 复制项目与规范化数据

把项目代码和已生成的 data/SSDD 整体放到服务器项目目录。无需复制 VOC 或原始 172MB 全目录；图片与所有 JSON 的相对布局保持一致。如果仍放在默认 data/SSDD，可不设置变量。

```bash
export SSDD_DATA_ROOT=/mnt/ssdd
python -c "import os,pathlib; p=pathlib.Path(os.environ['SSDD_DATA_ROOT']); print((p/'images').is_dir(), (p/'annotations/train_norm.json').is_file())"
```

预期输出：True True。耗时：检查小于 5 秒，传输时间取决于网络。失败处理：变量必须指向包含 images 和 annotations 的规范化数据根；保留文件名大小写。示例挂载点由你替换。

## 2. 创建独立环境并换 Linux wheel

```bash
conda create -n mmdetection python=3.10 -y
conda activate mmdetection
python -m pip config --site set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
python -m pip install 'numpy<2'
python -m pip install torch==2.1.0+cu118 torchvision==0.16.0+cu118 --index-url https://download.pytorch.org/whl/cu118
python -m pip install mmcv==2.1.0 --no-index --find-links https://download.openmmlab.com/mmcv/dist/cu118/torch2.1/index.html --only-binary=:all: --no-deps
python -m pip install -r requirements-lock.txt
```

预期输出：pip 根据 Linux / Python 3.10 自动选 manylinux wheel，版本完全不变；不使用 Windows 的 win_amd64 wheel。耗时：10–30 分钟。失败处理：确认服务器为受支持的 Linux x86_64 平台；无对应预编译 wheel、索引 404 时停止报告，禁止源码编译 mmcv。

## 3. 核对 CUDA 与配置

```bash
nvidia-smi
python -c "import torch,mmcv,mmdet;print(torch.__version__,torch.version.cuda,mmcv.__version__,mmdet.__version__)"
python tools/check_environment.py
```

预期输出：驱动可识别 GPU；版本行是 `2.1.0+cu118 11.8 2.1.0 3.3.0`，CUDA NMS 与两个配置通过。耗时：10–30 秒。失败处理：驱动必须支持 CUDA 11.8 wheel；不要因 nvidia-smi 显示其他 CUDA 上限就改 torch 版本。环境校验失败先让服务器管理员处理驱动。

## 4. 用等价入口启动

```bash
bash scripts/train.sh
```

预期输出：12 epoch、有效 lr=0.0025、验证出现 coco/bbox_mAP。耗时：40–70 分钟仅为原笔记本参考，云 GPU 不适用此承诺。失败处理：按常见报错排查；使用不同 GPU 后重新测 FPS 并记录实际 GPU/驱动，不直接沿用本机吞吐数据。
