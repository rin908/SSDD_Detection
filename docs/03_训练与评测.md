# 03 训练与评测

以下命令供你完成安装与数据准备后执行；交付时没有运行训练、测试或 FPS。先激活 `mmdetection`，在项目根执行。训练使用验证集选择最佳权重；测试集只在最终评测使用，不用于调参。[超参表](超参表.md)解释 lr、输入和随机性。

## 1. 启动训练

PowerShell：

```powershell
./scripts/train.ps1
```

Linux/Bash 等价：

```bash
bash scripts/train.sh
```

预期输出：单卡有效学习率 0.0025，开始 12 epoch，验证日志出现 `coco/bbox_mAP`。日志和权重在 `work_dirs/faster_rcnn_r50_fpn_ssdd/`；最佳权重名通常为 `best_coco_bbox_mAP_epoch_*.pth`。耗时：预计单卡 40–70 分钟，仅供参考，受功耗、存储和散热影响；首次 ImageNet 权重下载另计。失败处理：见 [常见报错](04_常见报错.md)，CUDA OOM 依次降 batch、分辨率、开 AMP；禁止直接换版本。

## 2. 恢复训练或选择变体（可选）

```bash
python tools/train.py --resume
python tools/train.py --config configs/faster_rcnn_r50_fpn_ssdd_1024.py
python tools/train.py --original
```

三条是不同用途，按需单独执行。预期输出：依次为恢复最新 checkpoint、1024×1024 / batch=1 / AMP、未去重对照训练。后两者分别写独立的 `_1024` 和 `_original` 工作目录；对照验证集不变。耗时：恢复只训练剩余 epoch；新实验参考 40–70 分钟，变体可能不同。失败处理：恢复前确保上次权重和同一配置存在；对照需先生成 `annotations/original/`。

## 3. 最终评测完整测试集

以下完整命令用固定存在的最后一轮权重演示。正式报告建议将 `--checkpoint` 换成日志记录的最佳验证权重；后续 FPS 使用**同一权重**。

```bash
python tools/evaluate.py --checkpoint work_dirs/faster_rcnn_r50_fpn_ssdd/epoch_12.pth
```

预期输出：CocoMetric 的 AP、AP50、AP75、AP_S、AP_M、AP_L，写入 `results/faster_rcnn_r50_fpn_ssdd/metrics.json`，自动更新 `results/summary.md`。耗时：约 1–5 分钟。失败处理：检查权重和数据路径；未生成权重时不能评测。数值必须以实测为准，不预填准确率。

## 4. 独立统计 Params

```bash
python tools/count_params.py
```

预期输出：backbone、neck、rpn_head、roi_head 与 total_M 表格，约 41M（精确值以脚本为准），写入同一 metrics.json。耗时：10–30 秒。失败处理：先运行环境检查；此工具不需数据、训练权重或 GPU，不初始化预训练权重，不下载文件。统计所有参数（包括冻结参数）、去除共享参数重复计数，不计 NMS 等后处理。

## 5. 独立测 FPS 与 latency

```bash
python tools/benchmark_fps.py --checkpoint work_dirs/faster_rcnn_r50_fpn_ssdd/epoch_12.pth
```

预期输出：GPU、驱动、FPS、latency(ms) 表格及输入 pipeline，同时写入 metrics.json。耗时：约 1–5 分钟。失败处理：需要 CUDA、同一权重和规范化测试图片；先过 CUDA NMS 冒烟检查。

口径：batch=1、FP32，关闭 AMP/TF32，预热 50 次，随后 200 次。每次计时前后 `torch.cuda.synchronize()`，统计平均单次秒数，FPS=1/平均秒数、latency=平均秒数×1000。包含每次从文件路径读图、缩放/补齐、CPU→GPU、网络、NMS、GPU→CPU 和 Python 列表输出；不含模型加载、可视化和写结果文件。按测试文件名排序循环取图；操作系统文件缓存可能已热，不声称测量冷磁盘。

指标附带实际 GPU、驱动、torch/CUDA 和输入 pipeline。基础输入保持比例，实际 tensor 会补齐到 32 倍数；变体输入为补零后的 1024×1024。笔记本显卡功耗模式会影响测量，建议接电并关闭其他 GPU 任务。1024 变体即使训练用 AMP，本工具仍测 FP32。

## 6. 子集评测（可选，仅评测）

```bash
python tools/evaluate.py --checkpoint work_dirs/faster_rcnn_r50_fpn_ssdd/epoch_12.pth --subset inshore
python tools/evaluate.py --checkpoint work_dirs/faster_rcnn_r50_fpn_ssdd/epoch_12.pth --subset offshore
```

预期输出：分别评测 46/186 张，metrics.json 新增独立子集条目，不覆盖主 test。耗时：每项约 1–3 分钟。失败处理：检查 subsets 标注；不从这些子集另切训练集。子集摘要的 FPS 留 N/A，因为完整测试 FPS 不代表子集独立基准。

## 7. 重新汇总已有结果

```bash
python tools/summarize.py
```

预期输出文件：`results/summary.md`，每个测试行包含 AP、AP50、AP75、AP_S、AP_M、AP_L、Params、FPS 共 8 项。训练 scalar 日志的验证 AP 与 loss 单列，绝不冒充测试 AP；未测项为 N/A。耗时：通常小于 5 秒。失败处理：查看各实验 metrics.json 是否完整；没有结果时只有表头是正常状态。

训练结束（包括中断的 finally）、评测完成、Params/FPS 完成后都会自动调用汇总。训练日志位于 `work_dirs/**/vis_data/scalars.json`，原始文本日志与 checkpoint 也保留。

所有工具支持 `--config`、`--original`、`--work-dir`、`--cfg-options`。对同一实验，评测/Params/FPS 必须使用相同配置与工作目录；工具检查模型/输入配置指纹和权重 SHA256，拒绝把不同权重拼成一行。切换权重时，例如给所有统计命令追加 `--work-dir work_dirs/report_best`。原版对照评测和基准都要加 `--original`，并传对应权重。不要并行写同一个实验的 metrics.json。
